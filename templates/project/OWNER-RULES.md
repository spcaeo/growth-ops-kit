# The owner's rules for this project

The book's default working rules (`book/02-owner-rules.md` in the kit) apply to every project. This file holds only what the
owner of **this** project adds or changes. Where a row here is stricter than a default, this file wins. Where a row
reverses a default, write the default's name in the first column and say so.

It starts empty on purpose. Rules come from the owner's own words, one at a time.

## How to add a rule

1. The owner says it. Log it first in `docs/steps-log.md` (flow stage F): their words, the date, what it means.
2. Add one row above: **the rule's name** (date) in the first column; in the second, what it means and why, in one or
   two sentences. Use "must" and "never" or a number. No "should", "try" or "ideally".
3. If a program can check it, add the check to the gate and an entry to `rules/registry.json` in the same change. A
   rule that lives only in this file is a guideline, not a rule.
4. If the rule would help every project, propose it back to the book.
